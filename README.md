# 小狸子 · 工程名词卡片墙

> 给「每个字都认识、拼起来不知道在说什么」的初学者用的 **102 张可翻转卡片**。

一个刚进计算机专业的人，最难受的不是学不会，而是**听不懂别人在聊什么**。

室友随口一句「我用 R 跑一下这个」「这个模型量化过」「先 docker 封起来」，你只能点头。
不是笨，是**缺一层词汇表**——而这一层，从来没人系统给你。

这个项目就是那层词汇表。**不教你把它用起来，只帮你把它认出来**：
听到一个名词时，你能立刻想出「哦，那是第几环的东西、大概是干什么的」。

**👉 直接打开：[工程名词卡片墙.html](工程名词卡片墙.html)**（单文件、零依赖、离线可用）

---

## 它长什么样

102 张卡片，每张正面只有名字和它属于哪一环；点一下翻面，背面是：

| 层 | 内容 | 说明 |
|---|---|---|
| 一句话 | 它是什么 | 30 字内，说人话 |
| 记： | 记忆口诀 | 压到最短的那一句 |
| 六个方向 | AI · 嵌入式 · 服务器 · 数据 · 论文 · 通用 | 每个方向几个点 + **一句"它在这有什么用"**，不是拍脑袋打分 |
| 同族 | 相邻概念 | 可点击跳转，让名词连成网而不是孤岛 |
| 🔎 再深一层 | 详细解读 + 别搞混 + 去哪学 + 第一次上手 | 见下 |

**「再深一层」是重点**：它不是一堆链接，而是先给你 **2～3 段正文**讲清「它到底是什么、为什么会有它、你在哪一步会撞上它」，再单独列出 **最容易搞混的地方**，最后才给官方文档 / 中文教程 / 视频 / 搜索关键词 / 一个"今晚就能做"的动作。

全站正文约 **1.6 万字**，平均每张卡 200 字。

## 骨架：科研八环

名词不是一锅乱炖，它们按「一个项目从选题到交出去」的顺序归位（括号里是当前张数）：

```
底座 · 贯穿全程 (16) ── Linux 命令行 / Shell / SSH / tmux / 权限 / WSL / grep / curl
第 1 环 选题与文献 (11) ── arXiv / 综述 / Zotero / 影响因子 / 会议 vs 期刊 / 大创
第 2 环 环境与复现 (8) ── Docker / 镜像与容器 / Dockerfile / 虚拟环境 / 依赖地狱 / CUDA
第 3 环 代码与版本 (22) ── Git / commit / branch / merge / PR / CI / 调试器 / Makefile
第 4 环 数据与处理 (8) ── Python / pip / numpy / pandas / SQL / R / matplotlib
第 5 环 实验与监控 (17) ── GPU / 显存 / OOM / Slurm / 超参数 / baseline / 消融实验
第 6 环 写作与图表 (4) ── LaTeX / Overleaf / 矢量图 vs 位图 / TikZ
第 7 环 协作与评审 (3) ── README / 异步沟通 / 文档与 Wiki
第 8 环 复现·交付与归档 (13) ── 复现 / 随机种子 / 实验记录 / 量化 / ONNX / 部署
```

背后依据是那句被反复引用的划分——**计算机有两类能力：理论走深度，系统走广度**。
学算法、刷题练的是前者；这个项目补的是后者：**在众多技术里挑出能凑成一套的那个组合**。

## 怎么用（给第一次打开的人）

**三轮过卡法**，大约三次就能"认全脸"：

1. **第一遍（20 分钟，不求记住）**——只看核心卡，一张张翻过去。目的只有一个：让名字从"陌生"变成"见过"。**别停下来背。**
2. **第二遍（每环 5 分钟）**——按环筛选，一环一环过。这次只盯背面那行 `记：`。第 2、3 环值得多停两分钟。
3. **第三遍（自测）**——把卡片翻回正面，自己张嘴说出它是干什么的，说不出来的点「还不行」。顶部「已记 N / 102」就是进度条。

还有两个专门为"听懂别人说话"做的入口：

- **🔎 我听到一句话**：把室友的原话整句贴进去，它拆出命中的卡片，并告诉你这句话**横跨了哪几环**（是在讲一个单点，还是在讲一条链）。
- **🎲 随机抽一张**：自测用，答完自动记进度。

> ⚠️ 这一版的目标是**认脸，不是会用**。能用是后面的事，那时候你手上会有真项目，学一个顶现在十个。

## 欢迎大家完善

这个项目最需要的就是**「又有一个词我听不懂了」**这种反馈。

- **发现某个名词没被收录** → 开 [Issue](../../issues) 把原话贴进来，越口语越好。
- **发现解释写错了、或者你看不懂** → 同样是 Issue，"看不懂"本身就是有效反馈。
- **想直接加卡 / 改文案** → 提 Pull Request，模板和规范都在 [CONTRIBUTING.md](CONTRIBUTING.md)。
- **想加自己专业方向的名词**（生信、量化、图形学、嵌入式……）→ 尤其欢迎，这个项目现在的偏向是 AI + 系统，别的方向还很空。

不需要你写得完美，**能让人看懂就够了**。

## 它不承诺什么

- 不是教程，看完不会让你会写代码。
- 不保证每个解释都对到学术级精确——它面向的是"第一次听说的人"，有些地方为了好懂做了简化。发现不严谨，请直接开 Issue 骂（礼貌一点就行）。
- 不追新。新名词会加，但优先级是"长期有用的"高于"这周很火的"。
