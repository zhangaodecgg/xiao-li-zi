工程广度地图

v2 · 从"工具清单"改成"能力坐标系" · 2026-10-16

计算机科学有两类根本问题。一类是理论：算法、数据结构、复杂度、机器学习。一类是系统：操作系统、网络系统、分布式系统、存储系统。理论走的是深度，追问在给定算力约束下如何把问题解决得更快更好；而系统走的是广度，追问对于现实需求如何在众多技术中设计出最"多快好省"的技术组合。搞 ACM 的人只练第一类——可惜第二类能力没有简单的测量方法，所以很多系统的苗子慢慢消隐了。

来源：知乎《什么才算是真正的编程能力？》下的高赞回答（多处转载，原文可查）

二、真正要换的是判断标准：两种思维

维度理论思维（你已很熟）工程 / 系统思维（要练的）
关注点正确性、完整性可行性、成本
方法理想化方案权衡与折中
目标完美解决实用解决
约束约束较少多重约束同时压过来
路径深度优先，求最优解广度优先，求平衡解
容错必须 100% 正确允许可控的妥协
遇到硬骨头花三天挖到源码层一天内找 workaround，记下问题后续优化

四、名词归位：你听过的词都在哪一格

名词落在哪一环它的真实身份
R 语言第 4 环和 Python 同类的语言，统计 / 生信圈常用——只是一个选项，不是新世界
Docker / 容器第 2 环让集群和笔记本跑出同一个结果的那把锁
Git第 3 环版本回溯 + 分支协作，从第一行代码就该用
GitHub第 3 / 7 环托管，以及让别人的眼睛进到你的代码里
CI 绿勾第 3 环推代码后自动跑测试，红叉绿勾就是它
模型量化第 5 → 8 环把模型压到能部署；剪枝、量化、蒸馏是一家人
显存 OOM第 5 环算力观测的一部分，不是玄学
Linux 命令行贯穿 2–5 环它不是某一环，是这些环的公共底座
复现 / 随机种子第 8 环科研的硬要求：别人能跑出一样的结果
